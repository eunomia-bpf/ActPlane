# Pre-model infrastructure repairs

Initial bootstrap and resource parsing repairs preceded all host expansion models. Later image-inventory repairs preceded the affected tasks' first model attempts, after some other host pilot outcomes already existed. The VM environment amendment follows those host pilots and precedes every guest-primary outcome; no host defended attempt had valid native-denial instrumentation.

- The dependency bootstrap initially passed an unsupported `--prepare` argument to the existing dependency helper. The native environment was installed, and the helper was rerun through its supported default entry point. The original log is retained.
- The Workspace root filesystem rejected nested `overlay2`; the private empty daemon was restarted with native Docker `vfs`. Every added condition uses the same recorded backing. The failure and successful actual storage receipts are retained.
- The first protein-assembly read-only inventory used a durable output-root path for its source script rather than the synced source path. That setup subprocess failed before any model call. Its traceback/log are retained; stderr from that first invocation was not separately persisted. The script now resolves its actual source file and records future failed inventory stdout/stderr. The model, task bytes, oracle and selected cohort did not change.
- Independent review corrected legacy resource-unit parsing before outcomes; all selected task names and hash ranks remained unchanged. The original and corrected catalog commits remain available.
- Some official images have no Python executable before agent setup. Their read-only inventory initially failed with exit 127, before a model attempt. The inventory now mounts the already hash-verified official public CPython 3.13.9 runtime under `/inventory` in the separate read-only/no-network inventory container. That mount is excluded from scanning and never enters an official agent container. Failed inventory receipts remain; the same selected tasks are retried without changing their official image or task configuration.
- Initial guest API attempts could not resolve the original internal gateway hostname. The Workspace host resolved it and authenticated `/models` successfully; independent direct-IP probes with the unchanged Host/auth succeeded on every guest. The repair adds only that original hostname's host-resolved address to each guest controller's hosts file, preserving the exact model, key, URL, prompts and defaults. Existing native attempts with the connection error, zero dispatched tools and no verifier execution remain infrastructure exclusions with per-trial audit evidence. All are retained; no genuine task outcome is resampled.
