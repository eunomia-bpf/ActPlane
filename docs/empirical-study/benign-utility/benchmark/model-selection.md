# Main-model selection and preflight deviations

Before main-matrix task outcomes, select the provided `zai/glm-5.3` gateway model with Harbor Terminus 2 defaults. Initial Qwen preflights spent large default completion budgets between shell actions. GLM produced shell actions at a practical rate without modifying the official agent timeout, decoding parameters, prompts, tasks, or verifier. Preserve Qwen candidate outcomes and all infrastructure failures in `trials.csv`; none belongs to the main matrix.

Early exploratory runs incorrectly passed Workspace namespace PIDs into a kernel interface expecting initial namespace PIDs. Their independent source observer saw no benchmark effects, so their security coverage is incomplete regardless of official verifier outcome. A subsequent mapper using the bpftrace `pid` builtin returned a helper error and zero; that attempted engine was detached. Main runs instead obtain `curtask->tgid` from a unique comm marker executed by the actual persistent shell, save the kernel receipt, reject nonpositive values or helper errors, and require independent evidence of a calibration child before starting the agent. This calibration adds no secret source or attack to the dataset.

Broad sources use supported suffixes that cover bare relative filenames as well as absolute paths. For example, the `.env` suffix also includes `project.env`; this is a documented filename overapproximation. Narrow sources retain explicit absolute credential paths, so tracepoint relative-path spelling remains a coverage limitation. The scoped OpenSSL sources come directly from the official task: `server.key` is private and `server.pem` combines that key with its certificate. No trusted declassification gate is evaluated.

Some tasks manipulate semantic secrets outside filename sources, such as historical Git objects, executable-embedded flags, and arbitrary repository files. Successful completion with no intervention does not demonstrate protection of these secrets. The model controller/API process is outside the protected tmux shell subtree, and model-context taint is not assumed.

The separate `enforcement_control.py` check uses an isolated helper process and filesystem outside every official trial. It reads a fixture at the declared private-key path and attempts a connection under the same compiled policies. The undefended helper exits normally, while each defended helper terminates with a successful kernel kill receipt. `results/enforcement-control.csv` records the initial-namespace root, actual return code, event counts and binary/policy hashes. These controls validate forced failure only and never enter benchmark task-success or intervention rates.

Security rates use actually dispatched Terminus terminal tool calls. Native ATIF also includes nonterminal `mark_task_complete` calls that do not dispatch shell commands. Initial preflight interpretation mistakenly described the difference as unexecuted proposed commands. Inspection of the actual native function names corrected that inference: the observed difference is completion markers, and completed main trials' `bash_command` counts match dispatch receipts. Exports now distinguish all native calls, native command calls, nonterminal calls and genuinely unexecuted or unmapped command calls, preserving matched native IDs. Socket observations are split by address family: Unix-domain connections are not Internet egress. Kernel-loader messages remain in raw logs; the model sees terminal process failure but does not receive the higher-level AgPlane semantic feedback interface.

`source_read_accesses` counts the independent observer's candidate secret-file read-access attempts. Its filename filter intentionally also includes semantic-secret candidates such as `secret.txt` that the policy may not label. A read-permission probe is not evidence of successful byte transfer or an actual `SECRET` label. The observer resolves paths, whereas tracepoint source matching can see a relative user spelling, so path agreement and label engagement must not be assumed from these counts alone.

An independent replay control found that both the global bpftrace string limit and the explicit `path()` buffer must accommodate long paths. Future trials record the enlarged launch setting in `scope.json`; the CSV also records each copied observer hash, explicit buffer and effective limit. Earlier main trials used the bounded legacy setting. Rows with helper errors are excluded from complete coverage, while error-free earlier rows retain their actual bounded configuration. Earlier launch-time engine hook environment was not recorded and remains unavailable. New launch receipts capture only the inherited hook-profile variables without changing them. Current export-time settings are recorded separately and must not be treated as historical launch evidence. The controller's exclusion from the protected root remains a limitation regardless of optional IPC hook support.

## Verifier transport repair and corrected primary cohort

Native verifier logs established that numerous reward-zero rows never ran the official tests: the prescribed GitHub download of uv failed, followed by missing `env` and `uvx` commands. These native rewards remain in the exports but cannot measure task failure or model capability. Native CTRF reports or explicit pytest result summaries establish verifier execution; bootstrap failures and unverified collection errors remain separate.

Before any corrected main outcome, declare a uniform primary cohort using the existing frozen task/condition matrix, agent/model defaults, official timeouts and unchanged task/test bytes. The native `verifier.env` supplies the official installer's supported `UV_DOWNLOAD_URL` override to a private cache of the exact official uv release, verified against its published checksum. The independent dependency control verifies the prescribed package versions and native CTRF generation. The same enlarged observer setting is used throughout this corrected cohort. No task assertion or success oracle changes.

All legacy attempts, including earlier verifier-valid outcomes, remain supporting records. Primary selection is the earliest verifier-valid, instrumentation-complete corrected attempt per task and condition, regardless of success. Known bootstrap failures are not failures of the model or defense. Repair attempts retain unique names and native outputs; collection errors require evidence review rather than automatic resampling. This declaration corrects infrastructure and measurement comparability, without selecting outcomes or changing the research question.
