# Review of concurrent LSM loader semantics

An initial review inferred that the retained `enforce_socket_connect` hook could lose a denial to a later loader because its C signature does not consume a prior-return argument. That categorical inference is withdrawn. The hook signature alone does not establish how the kernel invokes multiple attached programs.

The upstream x86 implementations for both the recorded older kernel tag and the new guest kernel family classify non-void `BPF_LSM_MAC` hooks as modify-return trampolines. Their generated trampoline branches to the exit path after a nonzero program return, skipping subsequent modify-return programs. The relevant primary sources are [Linux v7.3-rc3 attach-type mapping](https://github.com/torvalds/linux/blob/v7.3-rc3/kernel/bpf/trampoline.c#L769), [v7.3-rc3 x86 modify-return invocation](https://github.com/torvalds/linux/blob/v7.3-rc3/arch/x86/net/bpf_jit_comp.c#L3160), [Linux v6.12 attach-type mapping](https://github.com/torvalds/linux/blob/v6.12/kernel/bpf/trampoline.c#L474), and [v6.12 x86 modify-return invocation](https://github.com/torvalds/linux/blob/v6.12/arch/x86/net/bpf_jit_comp.c#L2604). The [LSM documentation](https://docs.kernel.org/bpf/prog_lsm.html) also illustrates preserving a previous return, but that coding example alone is not evidence that these x86 trampolines overwrite a nonzero result.

Consequently, concurrency alone does not demonstrate that any retained replay denial was shadowed, and it does not justify changing the existing replay counts or semantic labels, quarantining the cohort, or rerunning it. No such data changes were made in this review. A single-loader control is not a direct syscall-exit receipt for every historical event; the retained kernel/engine semantics and controls remain the basis for interpreting those events. This review does not assert exact source equivalence for every vendor patch or a new per-event return measurement.

The new benchmark's separate guest kernels remain a valid conservative execution arrangement. They are an environment choice, not evidence of a confirmed engine defect. No engine change or optional concurrency probe is needed before the new primary tasks proceed.
