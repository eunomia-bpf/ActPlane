# Open coverage gaps

## Trusted declassification is not yet evaluated

The selected official tasks and public trajectories have no established trusted redaction gate. The current compiler lowers executable patterns to comm basenames, so an apparent gate path alone cannot authenticate code provenance. Installing a same-name executable is not a trusted scrub operation. We will not insert artificial gate calls into official tasks or claim that source narrowing validates declassification. Condition (c) currently measures source narrowing only. A trustworthy gate deployment and real gate use remain missing evidence for the full requested condition.

Independent source review confirms that the evaluated scoped policies declare no declassification updates. The official Git sanitization/recovery tasks ask the agent to edit local content; they do not supply an independently trusted redactor before egress. The fixed public-trajectory inputs likewise provide no established gate. The absence of a gate in these workloads is a coverage limitation, not evidence about the utility of trusted declassification.

## Session-wide context coverage remains unmeasured

The official Terminus controller/model API runs outside the protected task shell subtree. Public replay similarly forks commands from a retained worker and does not replay model-context information flow. A child process opening a source does not automatically label the controlling parent. Utility numbers for this deployment cannot settle the reviewer example in which secret contents persist in the model's session context.

## Native denial capability is verified

The initial claim that host BPF-LSM was unavailable is withdrawn. Actual kernel inspection lists BPF in the active LSM chain, and the retained loader reports enforce mode. A separate same-engine native-block control now records EPERM and successful denial while the process survives. Native IPv4 connection denial will therefore be the requested primary comparison. Existing `kill`-only trials establish forced failure with `blocked=false` and remain supporting observations; their utility cannot be substituted for block or mixed into its rows. No shared kernel reboot or deployment change was made. This capability is no longer an execution blocker.

Other runnable benchmark, policy-scoping and replay work continues. Setup/preflight failures and unsupported repository directives are retained in their respective machine-readable result files rather than silently removed.

## Complete network-egress confinement is not established

Independent retained-source review confirms that the executed policies deny SECRET-conditioned new IPv4 `connect` attempts in the mapped process subtree. Their compiled sink is `TOP_CONNECT`; the retained native block hook checks AF_INET socket connection creation. These observations do not cover existing or inherited socket writes, accepted-socket server responses, IPv6 or unconnected UDP sends. In enforce mode, the alternative tracepoint send-address path does not supply a native block for those operations. A server's private-key read therefore does not guarantee engagement of the tested sink. The measurements must not be described as complete enforcement of all secret-to-network traffic.

## Shared disk pressure

During setup the shared volume rose from its initial low utilization toward the user's ceiling, while this lane retained only its first benchmark image. The matrix checks capacity before each cell and prunes only images in its own isolated Docker daemon. Another lane's state will not be removed. If the next official image cannot fit below the ceiling, that cell must remain pending until capacity becomes available. Raw capacity receipts are retained remotely by the benchmark worker.
