# Prospective repository holdout for enforcement/context rescue

The original full reference was already evaluated and aggregate confusion diagnostics were inspected before this follow-up. This split is held out from the rescue's codebook development and selection, not an untouched external holdout. No independence from those earlier aggregate observations is claimed. The operator supplied the concrete-project-binding interpretation before the split. The exact historical prompt and human review sample remain unavailable.

`prepare.py` fixes the repository split using the seed in protocol.csv. Development contains the first floor(N/3) shuffled repositories, and all remaining repositories form test. No statement can cross repository partitions. Selection is independent of labels, repository size and prior per-repository performance. The original source labels remain immutable.

Only development rows may supply few-shot examples, error inspection, or revisions. At most three codebook revisions are permitted. After each revision, both named primary models and anonymized Qwen adjudication are evaluated on dev. Stop early when both adjudicated dev kappas meet the prespecified early-stop threshold. Otherwise choose the revision with the highest minimum adjudicated dev kappa, breaking ties by mean kappa and then earlier revision. Freeze the codebook, selected examples, input-context policy and hashes before the test pass. Earlier revisions record test status `not_evaluated`; only the chosen revision receives test scores. Test outputs may be cached/retried for transport/schema failures without inspecting gold or changing the guide. There is one test analysis, with no subsequent codebook tuning.

Evaluate enforcement on gold directives. Evaluate context on gold system-observable directives, counting predicted inapplicable context as disagreement. Type and topic are fixed from the historical reference during calibration and from the already accepted scaled labels during deployment. No type/topic label is retuned. Each dimension passes when its adjudicated test kappa and coverage satisfy protocol.csv. Raw context headlines additionally depend on enforcement passing because their system-observable denominator uses enforcement. Every primary and adjudicated score, missing label and confusion cell is reported.

Inputs include unannotated source text: statement, repository-relative path, enclosing Markdown headings and paragraph. Source context supplies referents, not additional labeling targets. Paragraphs are bounded to 2,000 characters per statement and heading paths to 500 characters, using the same deterministic extraction for dev, test and new corpus. Source hashes and context hashes are committed. Descriptions do not receive enforcement/context labels. Joint enforcement/context output preserves applicability. Only dev labels can appear as few-shot examples. Gold test labels never enter requests.

The final guide may be applied to the enlarged corpus concurrently with the frozen test inference to meet the deadline. Until the test gate is known, these predictions have no headline status. Failed-axis source predictions are used only for explicitly exploratory error-corrected estimates. No inference result can change the frozen guide or split.

Correction uses the test confusion matrix P(predicted class | reference class) and constrained multinomial mixture estimation on the simplex. Report enforcement class prevalence, system-observable prevalence, OS-tier candidate fraction/count, context-required prevalence (using a joint enforcement/context confusion matrix), and project cross-event share (using a separate repository-level binary confusion matrix). Corrections assume transportable class-conditional error from the old coding-file reference to the larger, changed corpus. This is unverified, particularly for new families/noncoding tasks. Singular/ill-conditioned matrices, missing test classes, boundary estimates and unsuccessful bootstrap fits are retained and flagged, not silently regularized into certainty. Repository bootstraps resample test repositories and new repositories independently, preserving new discovery strata. Intervals include confusion-matrix uncertainty and observed-corpus variability, but not codebook-selection uncertainty, earlier diagnostic exposure or unmodeled domain shift. No correction is applied to the already calibrated type/policy fraction.

All old calibration failures, gates, predictions and figures remain recoverable in branch history and the initial CSVs. Rescue deployment provenance explicitly identifies any superseding gate. Raw corrected estimates are never conflated with accepted automated labels. No paper source, deployment or PR is changed.
