## Historical recovery and calibration

`recover.py` exports the artifact branch by immutable commit without checking it out. It recovered 2116 labeled statements in 64 annotation files referencing 64 primary instruction paths. The corresponding artifact directories contain 93 raw instruction files (86 byte-distinct within repositories). Excluding 2 pure `@AGENTS.md` redirect files after byte deduplication yields exactly 84 files, 16,256 lines, and 1,136,161 bytes, reproducing the historical file denominator and size totals. However, annotation spans cover 10,209 lines in the primary referenced sources, so the recovered labels do not establish statement coverage of every additional instruction file. The cross-event repository share differs from the rounded paper claim and remains visible in the comparison table.

`taxonomy.txt` reconstructs the coding guide and examples in `origin/artifact-ready:docs/empirical.md` and the current motivation section. The exact historical invocation prompts and the human review sample were not located. This is a reconstructed prompt, not a claim of exact prompt replication. Gold labels are never sent to either model or to adjudication.

The primary annotators are the direct, identity-verified `qwen3.8-27b-nvfp4` endpoint and the gateway’s named `zai/glm-5.3` route. The gateway-reported model identity is recorded but its provider weights cannot be independently audited. GLM uses low reasoning effort because its reasoning cannot be disabled. Disagreements are reread by Qwen with anonymized primary labels. Adjudication is therefore correlated with a primary model, not an independent human reference.

## Selection and measurement

The eligibility floor is 100 stars with a push on or after 2025-01-01. Forks and archived repositories are excluded by the search. `collect.py` takes the top 100 results of each fixed query, unions within a discovery stratum, and visits candidates by descending stars with repository name breaking ties. Quotas are 200 general-software repositories, 75 additional agent-ecosystem repositories, and 50 additional repositories from noncoding discovery queries. Earlier strata own overlaps. A quota can remain unfilled if the fixed candidate set is exhausted. Discovery strata do not establish repository categories.

There is no language, creation-year, file-size minimum, directive-density, or subjective fake-star filter. This broadens the original study’s eligibility and avoids outcome-based filtering, but admits low-information files, collections, and potentially inflated stars. `collection_attempts.csv` retains unsuccessful probes and `searches.csv` retains queries and truncation indicators. GitHub’s ranking and search cap prevent an exhaustive population sample.

All requested families are inspected in recursive commit-pinned trees: CLAUDE.md, AGENTS.md, GEMINI.md, .github/copilot-instructions.md, .cursor/rules/*, .cursorrules, .windsurfrules, and SKILL.md. To bound very large skill/rule collections, at most 1 path per family per repository is analyzed, preferring fewer path components, shorter paths, then lexical order. Files above 128,000 bytes are excluded. All discovered paths, including capped paths and download failures, remain in the manifest. A truncated GitHub tree is flagged, so absence of a family in such a tree is not proof of absence.

Qwen proposes semantic statement starts in source chunks targeting 160 lines. The script derives half-open ranges and copies source text exactly. Coverage, hashes, and range continuity are checked, while extraction failures remain recorded. Earlier range-pair attempts that failed validation remain in the raw logs. This validates source fidelity, not the semantic correctness of boundaries. Chunking may separate context, and the new extraction has no human boundary audit. Calibration holds historical boundaries fixed and therefore does not validate new extraction quality.

Overall analysis counts each byte-identical file once within a repository. Family analysis attributes shared text to each family in which it appears, so family counts are not additive. Repository categories come from a separate metadata classifier and are explicitly marked as model judgments. A noncoding-agent repository can still contain coding instructions. The category breakdown must not be described as a noncoding-policy slice without inspecting file scope.

Repository-purpose groups are defined in `categorize.py`: agent_frameworks includes reusable agent infrastructure, coding agents, editors, and developer-agent tools; applications includes general software, libraries, services, and educational collections; noncoding_agents covers assistants primarily advertised for personal, office, research, browser, or finance tasks. Mixed systems are assigned by their primary advertised purpose. These categories have not received independent human reliability validation.

A separate `scope_files.py` classifier examines source excerpts to identify actual noncoding task instructions. `file_scopes.csv` preserves its decisions and rationales, and file-scope summaries are reported separately from repository categories. These scope labels have no human reliability calibration and may be affected by omitted middle content, so this is an exploratory noncoding slice. Both optional direct flash endpoints reject the available authentication; their recorded probes are in `endpoint_probes.csv` and they are not used. The optional OpenCode routes also reject requests with the requested session header, as recorded in `gateway_probes.csv`. A named GLM flash route was used only for a throughput pilot and is not part of the primary calibration.

Intervals use 2,000 bootstrap replicates resampling repositories within discovery strata, with seed 20261028. They describe sensitivity within this convenience sample. They do not correct star/query selection bias, model labeling error, duplicated templates across repositories, or changed eligibility since the historical snapshot. Comparisons are descriptive rather than evidence of temporal change. CSV delta intervals use independently resampled historical and new repositories.

Headline analysis requires every selected source file in a repository to have complete model pairs and final labels. Incomplete repositories remain in the collection and coverage tables rather than entering project-level denominators with unobserved files treated as negative. This makes interim checkpoints subsets of the final snapshot, not final results.

## Reproduction and artifacts

Use an isolated Python environment with `requirements.txt`. Set `GH_TOKEN`, `LITELLM_BASE_URL`, and `LITELLM_API_KEY` in the environment. Never pass secrets as command-line arguments. Raw responses, cached prompts/completions, source files, retries, and HTTP logs stay in the operator-specified raw directory. Set `ACTPLANE_CORPUS_RAW` to reproduce in a different raw-data location. Access to the named model endpoints is required.

```bash
python recover.py
python collect.py
python label.py --model qwen3.8-27b-nvfp4 --output calibration_qwen.csv
python label.py --model zai/glm-5.3 --workers 2 --batch-size 12 --output calibration_glm.csv
python label.py --model qwen3.8-27b-nvfp4 --primary calibration_qwen.csv --other calibration_glm.csv --output calibration_adjudicated.csv
python analyze.py --calibration-only
# Scale only the dimensions that passed. See run_scale.py for the gate-controlled pipeline.
python run_scale.py
python analyze.py
python figures.py
python report.py
```

Committed artifacts include immutable historical provenance, historical labels, model labels, calibration confusion tables, search queries, corpus/file manifests, extraction status, repository categories, summary tables, and the figures corresponding to the paper’s plots. GitHub requests are sequential, cached, and honor retry/reset feedback. Model concurrency stays within the operator’s endpoint limits.

The repository-requested `oss-change-workflow` skill was unavailable in the installed skill catalog and filesystem search. Work follows the explicit repository scope, validation, and documentation instructions. The operator’s updated handoff rule is to commit and push only to `experiments/corpus-scale-20261028`, with no further PR activity. No paper source, kernel code, cluster deployment, or other lane is changed.
